## Правила v2 (приоритетные)

Источники правды: docs/CONCEPT.md (содержание, структура, тон; написана владельцем) > docs/design-brief.md (визуальное направление) > PLAN.md и docs/PLAN-3R.md (процесс). При расхождении прав вышестоящий документ. Читай только нужный раздел, не весь файл.

@docs/HANDOFF.md

### Бренд и тексты
- Название только «ABSOLUTI» / «Абсолюти». Никаких Arts Club, Art Club, London и других придуманных уточнений: ни в интерфейсе, ни в метаданных, ни в коде.
- Не выдумывай факты: даты основания, имена, цифры, телефоны, адреса, ссылки. Данных нет: спроси владельца, а на публичной странице оставь пусто, не заглушку с выдумкой.
- Не добавляй пояснительные подзаголовки к разделам (Расписание, Новости, Фото) и новые разделы без согласования.
- Композицию главной не менять без согласования (исключение: фоновый слой, шаг B1 в docs/PLAN-3R.md).

### Не ломать
- Работает и должно остаться рабочим: все публичные маршруты, вход в админку (пароль + TOTP), чтение /content, `npm run build`.
- Перед правкой коммит. После правки `/regress`. Красное: чини или откати свою правку, дальше по плану не иди.
- Меняй только файлы, нужные шагу. Не рефакторь «заодно», не обновляй зависимости (next, react и т.д.) без вопроса.
- Без вопроса запрещено: `rm -rf` (кроме `.next`, `test-results`, `playwright-report`), `git reset --hard`, `git clean`, `git checkout .`, `git push`, удаление или перезапись файлов в /content, public/images и `.env*`.
- Один процесс Next за раз. Перед `npm run build` останови `npm run dev` (иначе ломается `.next`). Перед запуском проверь порт: `lsof -i :3000`. Если dev странно падает или пишет про error components, выполни `rm -rf .next` и перезапусти.
- Хуки плагинов (например Fact-Forcing Gate) не обходи через `cat >` или `sed -i`: выполни требование хука и повтори Write/Edit.
- Секреты не печатай и не коммить.

### Агенты
- Роли и исполнители в docs/TOOLS.md (нет файла: составь заново). Читающие задачи параллельно, пишущие по одному. Автор правки её не ревьюит: ревью делают design-reviewer, concept-auditor и агент ревью кода.
- Не хватает инструмента: установи как dev-зависимость, запиши в docs/TOOLS.md и в журнал.

### Сохранение состояния
- После каждого шага: запись в docs/PROGRESS.md и обновление docs/HANDOFF.md (команда /handoff). Перед закрытием сессии всегда /handoff.
- В начале сессии читай docs/HANDOFF.md и продолжай с указанного там шага.
